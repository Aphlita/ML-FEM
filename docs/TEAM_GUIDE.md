# A1-13 项目队员说明书

这份文档是给队员看的唯一入口。目标是让大家最快知道我们在做什么、现在做到哪、怎么运行、接下来能做什么。

## 1 项目一句话说明

我们正在做 A1-13 竞赛作品：围绕 ML-KEM 解封装实现，做一个能够完成时间检测、统计分析、定位、防护改造、复测和报告导出的实验平台。

平台最终应该形成这条链路：

```text
基本功能验证
-> 自动生成测试样本
-> 固定环境重复采集运行时间
-> 统计分析时间差异
-> 定位差异可能来源
-> 做常数时间防护改造
-> 复测改造效果和性能开销
-> 导出报告和复现材料
```

## 2 当前已经有什么

当前仓库是初始平台版本，已经完成：

- Web 平台基础框架。
- 后端 API 服务。
- 前端页面。
- ML-KEM-512、ML-KEM-768、ML-KEM-1024 基本功能接入。
- 生成、封装、解封装接口。
- 共享值一致性验证。
- 公开测试向量验证接口。
- 固定 CPU 核短实验计时检测接口。
- 时间检测结果前端展示。
- 基础测试脚本。

当前还没有完成：

- 标准的自动样本生成模块。
- 标准解封装计时实验模块。
- 完整统计分析模块。
- 定位模块。
- 常数时间防护改造。
- 改造前后复测。
- 报告导出。

所以现在它是“能跑起来的初始平台”，不是最终作品。

## 4 队员怎么把项目跑起来

### 4.1 克隆仓库

```bash
git clone <REPO_URL>
cd a1-13-mlkem-platform
```

### 4.2 构建

```bash
./scripts/build.sh
```

如果构建失败，先检查：

- 是否在 Linux 环境。
- C 编译器是否可用。
- Python 是否可用。
- `core/mlkem-native` 是否存在完整代码。

### 4.3 启动平台

```bash
./scripts/start.sh
```

默认监听：

```text
127.0.0.1:8000
```

如果在远程服务器运行，需要端口转发：

```bash
ssh -p <PORT> -L 8000:127.0.0.1:8000 <USER>@<HOST>
```

然后本地浏览器打开：

```text
http://127.0.0.1:8000
```

### 4.4 跑基础测试

```bash
python3 tests/test_basic.py
```

## 6 接下来最重要的模块

### 模块一 自动样本生成

目标：自动生成用于时间采集的不同类别输入。

要做：

- 生成正常样本。
- 生成固定位翻转样本。
- 生成格式扰动样本。
- 生成验证失败样本。
- 保存样本类别、扰动位置、随机种子、生成时间。

输出：样本文件、元数据 JSON、前端样本统计展示。

优先级：最高。

### 模块二 标准计时采集

目标：围绕解封装函数做重复运行时间采集。

要做：

- 固定 CPU 核。
- 设置采样次数。
- 对每类样本重复运行。
- 保存每次运行时间。
- 记录环境参数。

输出：原始时间日志、环境信息、采样参数。

优先级：最高。

### 模块三 统计分析

目标：判断不同样本类别的时间分布是否可区分。

要做：

- 均值、方差、标准差。
- 中位数、P90、P95、P99。
- 置信区间。
- Welch t 检验或 Mann Whitney U 检验。
- 自动输出结论。

输出：统计表、图表、自动判断。

优先级：最高。

### 模块四 报告导出

目标：把实验结果自动整理成提交材料。

要做：

- 导出环境信息。
- 导出样本生成规则。
- 导出统计图表。
- 导出定位结果。
- 导出前后对比结果。
- 打包日志和脚本。

输出：报告草稿、实验日志包、复现说明。

优先级：高。

### 模块五 定位

目标：当发现时间差异后，说明差异可能来自哪里。

要做：

- 函数级计时追踪。
- 把关键函数和 ML-KEM 流程对应起来。
- 检查条件分支、提前返回、比较函数、循环和错误处理路径。
- 可选做二进制检查。

输出：可疑位置列表、代码位置、解释说明。

优先级：高。

### 模块六 防护改造和复测

目标：修改实现方式，让不同类别输入的处理路径和运行时间尽量接近，并复测效果。

要做：

- 固定长度比较。
- 掩码选择。
- 固定循环次数。
- 统一错误处理。
- 复测改造前后时间分布。
- 计算性能开销。

输出：改造代码、前后对比图、性能开销表。

优先级：高，但放在前面模块之后做。


## 6.5 当前短实验代码在哪里

平台当前“固定 CPU 核短实验计时检测”调用的是仓库内这个目录：

```text
experiments/clangover-poc/
```

这里已经包含当前能产生时间差异结果的短实验源码，包括：

```text
attack.c
attack_bounded.c
Makefile
kyber/
liboqs/
```

其中 `attack_bounded.c` 是我们为了比赛演示改出来的短实验版本。它限制了实验规模和迭代上限，适合平台按钮快速调用。

首次运行前需要构建：

```bash
./scripts/build_timing_demo.sh
```

构建完成后会生成：

```text
experiments/clangover-poc/clangover-pqcrystal-kyber-bounded
```

平台的 `/api/timing-detect` 默认调用这个程序。

注意：旧日志和旧二进制不提交，队员需要在自己环境里重新构建和运行。
