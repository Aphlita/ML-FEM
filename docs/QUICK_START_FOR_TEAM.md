# 队员快速了解版

如果你刚加入这个项目，只看这一页也能知道现在发生了什么。

## 一句话说明

我们正在做一个 A1-13 竞赛平台：围绕 ML-KEM 解封装实现，完成时间检测、统计分析、定位、防护改造和复测报告。

## 当前项目不是最终版

现在仓库是初始平台版本，已经有基础页面和基础接口，但还缺几个比赛真正需要的核心模块。

## 已经有的东西

- 可以打开网页平台。
- 可以跑 ML-KEM 基本功能。
- 可以做公开向量验证。
- 可以调用一个固定 CPU 核的短实验计时模块。
- 可以展示部分时间差异结果。

## 现在最缺的东西

1. 自动样本生成。
2. 标准解封装计时实验。
3. 更完整的统计分析。
4. 报告导出。
5. 定位模块。
6. 防护改造和复测。

## 队员可以马上做什么

### 前端方向

先看：

```text
frontend/index.html
frontend/app.js
frontend/styles.css
```

可以做：

- 把页面改成实验流程式布局。
- 新增样本生成区域。
- 新增统计图表区域。
- 新增报告导出区域。

### 后端方向

先看：

```text
backend/server.py
backend/mlkem_service.py
```

可以做：

- 新增样本生成 API。
- 新增标准计时采集 API。
- 新增统计分析 API。
- 把结果保存成 JSON。

### 实验方向

先看：

```text
docs/MODULES_AND_TASKS.md
```

可以做：

- 设计不同类别的测试样本。
- 确定采样次数。
- 跑不同 CPU 核的对比。
- 整理实验数据。

### 文档方向

先看：

```text
docs/PROJECT_OVERVIEW.md
docs/MODULES_AND_TASKS.md
```

可以做：

- 写复现步骤。
- 写环境说明。
- 写设计报告大纲。
- 整理题目要求和我们模块的对应关系。

## 推荐开发顺序

```text
1 基础页面整理
2 自动样本生成
3 标准计时采集
4 统计分析
5 报告导出
6 定位
7 防护改造
8 复测对比
```

## 不要提交的东西

- 运行日志。
- 服务 PID。
- 服务器地址和密码。
- 个人 token。
- 临时结果文件。

这些已经通过 `.gitignore` 排除了，但提交前还是要看一眼 `git status`。

## 最重要的判断

如果一个队员不知道从哪里开始，就让他先做下面三个之一：

1. 前端：把页面改成更清晰的流程式页面。
2. 后端：实现自动样本生成接口。
3. 文档：把现有平台截图和功能写成设计报告草稿。
