# 模块和任务拆分

本文档把 A1-13 作品拆成具体模块。队员可以直接按模块分工。

## 1 基本功能模块

目标：证明 ML-KEM 基本功能接入正确。

要做：

- 支持 ML-KEM-512、768、1024。
- 支持生成、封装、解封装。
- 支持共享值一致性验证。
- 支持公开测试向量验证。

当前状态：基本完成。

后续优化：

- 前端展示更清楚。
- 把测试向量来源、通过数量、失败项展示完整。

## 2 自动样本生成模块

目标：自动生成用于时间采集的不同类别输入。

要做：

- 生成正常样本。
- 生成固定位翻转样本。
- 生成格式扰动样本。
- 生成验证失败样本。
- 保存样本类别、扰动位置、随机种子、生成时间。

输出：

- 样本文件。
- 样本元数据 JSON。
- 前端样本统计展示。

当前状态：未完成，优先级最高。

## 3 标准计时采集模块

目标：围绕解封装函数做重复运行时间采集。

要做：

- 固定 CPU 核。
- 设置采样次数。
- 对每类样本重复运行。
- 保存每次运行时间。
- 记录环境参数。

输出：

- 原始时间日志。
- 环境信息。
- 采样参数。

当前状态：已有短实验计时接口，但还需要改成更标准的输入分类实验。

## 4 统计分析模块

目标：判断不同样本类别的时间分布是否可区分。

要做：

- 计算均值。
- 计算方差和标准差。
- 计算中位数、P90、P95、P99。
- 计算置信区间。
- 加入 Welch t 检验或 Mann Whitney U 检验。
- 输出是否可区分的结论。

输出：

- 统计表。
- 图表。
- 自动结论。

当前状态：只有简单均值和阈值判断，需要增强。

## 5 定位模块

目标：当发现时间差异后，说明差异可能来自哪里。

要做：

- 函数级计时追踪。
- 把关键函数和 ML-KEM 流程对应起来。
- 检查条件分支、提前返回、比较函数、循环和错误处理路径。
- 可选做二进制检查。

输出：

- 可疑位置列表。
- 对应代码位置。
- 与流程的对应解释。

当前状态：未完成。

## 6 常数时间防护模块

目标：修改实现方式，让不同类别输入的处理路径和运行时间尽量接近。

要做：

- 固定长度比较。
- 掩码选择。
- 固定循环次数。
- 统一错误处理。
- 避免输出内部状态。

输出：

- 改造版本代码。
- 变更说明。
- 正确性验证结果。

当前状态：未完成。

## 7 复测与性能对比模块

目标：证明改造前后确实有变化，并说明性能代价。

要做：

- 在同样环境下重新采集数据。
- 比较改造前后均值、分位数、统计检验结果。
- 计算性能开销。
- 重新验证功能正确性。

输出：

- 前后对比表。
- 前后对比图。
- 性能开销百分比。

当前状态：未完成。

## 8 报告导出模块

目标：把实验结果自动整理成提交材料。

要做：

- 导出环境信息。
- 导出样本生成规则。
- 导出统计图表。
- 导出定位结果。
- 导出前后对比结果。
- 打包原始日志和脚本。

输出：

- 报告草稿。
- 实验日志包。
- 复现说明。

当前状态：未完成，但建议尽早做，因为比赛提交时很省时间。

## 9 建议分工

### A 同学 前端和展示

- 优化首页流程图。
- 增加样本生成页面。
- 增加统计图表展示。
- 增加报告导出按钮。

### B 同学 后端和数据

- 实现样本生成 API。
- 实现标准计时采集 API。
- 实现统计分析 API。
- 设计结果保存格式。

### C 同学 实验和分析

- 设计样本类别。
- 跑不同 CPU 核和不同采样次数实验。
- 整理统计结论。
- 写实验说明。

### D 同学 文档和报告

- 整理题目要求对应关系。
- 写环境说明。
- 写复现实验步骤。
- 整理设计报告。

## 10 最短可交付路线

如果时间紧，优先完成：

```text
基本功能验证
-> 自动样本生成
-> 标准计时采集
-> 统计分析
-> 报告导出
```

如果时间充足，再做：

```text
定位
-> 防护改造
-> 复测
-> 跨环境对比
```
